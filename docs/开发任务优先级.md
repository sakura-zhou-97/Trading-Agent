# 开发任务优先级

> 依据：`CONTEXT.md`、`docs/技术方案.md`、`docs/产品文档.md`、当前代码浏览结果。
>
> 目标：确认进入开发后的任务顺序，保证每一步都能独立验证，并且不破坏现有 A/B/C 筛选链路、CLI、复盘补丁池。

## 1. 当前项目浏览结论

### 1.1 主链路现状

当前项目有两条可用主链路：

```text
盘后筛选链路:
get_daily_universe
-> attach_struct_features
-> run_coarse_screen
-> calibrate_with_sector
-> run_story_analysis / run_story_analysis_2layer
-> analyze_candidates
-> results/screener/<trade_date>/

复盘迭代链路:
results/screener/<date>/
-> load_tracking_targets
-> track_three_day_metrics
-> generate_patch_suggestions / generate_ai_review_suggestions
-> append_proposals
-> results/iteration/<trade_date>/
```

对应入口：

| 入口 | 当前作用 |
|---|---|
| `screen-analyze` | 运行 A/B/C 筛选分析 |
| `daily-run` | 先筛选，再运行三日复盘 |
| `track-iterate` | 运行三日追踪和补丁建议 |
| `dashboard` | 读取现有 A/B/C/D/E 文件做控制台摘要 |
| `patch-status` / `patch-apply` | 人工采纳和应用补丁 |

### 1.2 现有可复用 Module

| Module | 当前 Interface | 可复用点 | 主要限制 |
|---|---|---|---|
| `dataflows/china/universe_provider.py` | `get_daily_universe(...) -> List[Dict]` | 能获取日线全市场涨幅候选，含行业、成交额 | 依赖 Tushare/Tinyshare，市场广度/涨跌停统计未显式封装 |
| `dataflows/china/batch_quotes_provider.py` | `attach_struct_features(...)` | 已计算 MA、量比、趋势、位置、突破 | 字段是散 Dict，没有 schema |
| `screener/coarse_rules.py` | `run_coarse_screen(...) -> CoarseResult` | 硬规则和粗筛标签已可用 | rulebook 中已有 `max_3d_mdd_pct` 但代码未使用 |
| `sector/sector_calibrator.py` | `calibrate_with_sector(...) -> Dict` | 已有行业聚合、龙头、板块乘数 | 不是显式 `SectorScore`，没有板块状态/适配器字段 |
| `analyzer/fine_filter_engine.py` | `analyze_candidates(...) -> Dict` | AI/fallback 决策卡成熟，失败可降级 | 决策卡不包含机会评分和交易计划 |
| `analyzer/story_two_layer.py` | `run_story_analysis_2layer(...) -> Dict` | 深度故事卡和 prompt_io 完整 | 成本高，不适合作为 V1 默认全量依赖 |
| `iteration/tracker.py` | `track_three_day_metrics(...)` | 三日追踪可用 | 只做 T+1/T+2/T+3，不支持 1/5/10/20 日和分组 |
| `iteration/patch_pool.py` | `proposed -> accepted -> applied` | 符合人工审核原则 | `patch-apply` 会真实写 rulebook/prompt，需要谨慎测试 |
| `pipelines/stock_analysis_pipeline.py` | `run_stock_analysis_pipeline(...)` | 现有编排和产物写入可复用 | 同时承担编排、渲染、trace、写文件，过重 |

### 1.3 关键风险

1. **字段契约风险**：当前阶段间大量使用 `Dict`，新增评分、计划、日报后容易字段漂移。
2. **流水线膨胀风险**：`stock_analysis_pipeline.py` 已经很胖，新产物继续写进去会降低可测试性。
3. **市场环境数据不足风险**：当前没有独立市场环境数据模块，V1 需要允许字段缺失并输出 `unknown`。
4. **测试不足风险**：仓库没有正式 `tests/` 目录，只有 `test.py` 手工脚本。
5. **补丁状态风险**：`rulebook_mvp.yaml` 和 Prompt 里已有历史补丁内容，开发时不能误删或重置。

## 2. 开发总原则

### 2.1 必须遵守的领域边界

来自 `CONTEXT.md`：

- **候选股** 只表示进入 `A_candidates` 的股票。
- **重点机会** 是经过 **机会评分** 后达到 S/A 的股票。
- **交易计划标的** 是有条件式 **交易计划** 的 **重点机会**。
- **AI 分析** 可以影响排序和风险提示，但不能直接提高 **仓位上限**。
- **防守市场** 下不生成新增仓位计划，仓位上限为 0。
- V1 是 **盘后系统**，不做实时盘中提醒。
- V1 做 **计划前向验证**，不做 **交易执行复盘**。
- V1 使用 **文件产物**，不上数据库。
- V1 不做 HTML 日报，只做 `R_daily_report.json` + `R_daily_report.md`。

### 2.2 技术策略

- 先加 schema 和纯函数，再接流水线。
- 先追加产物，不删除旧产物。
- `run_stock_analysis_pipeline` 对 CLI 保持兼容。
- 新 Module 必须支持 `enable_ai=False`。
- 日报 Markdown 必须从 `R_daily_report.json` 渲染。
- 每个切片都要有最小测试，优先测纯函数。

## 4. P0 任务

### P0-1：建立 schema 契约

**目标**

用明确 schema 固定 V1 核心对象，减少阶段间 `Dict` 漂移。

**建议新增文件**

```text
tradingagents/market/schemas.py
tradingagents/opportunity/schemas.py
tradingagents/planning/schemas.py
tradingagents/reporting/schemas.py
```

**核心对象**

| 对象 | 所属 Module | 用途 |
|---|---|---|
| `MarketEnvironment` | `market` | 市场状态、市场分、系统行为 |
| `SectorScore` | `opportunity` 或 `sector` | 板块语境评分 |
| `OpportunityScore` | `opportunity` | S/A/B/C 机会评分 |
| `TradePlan` | `planning` | 条件式交易计划 |
| `DailyReport` | `reporting` | 每日报告数据契约 |

**验收**

- schema 能被单元测试直接构造。
- 所有字段有默认值或明确必填。
- `TradePlan` 支持 `plan_status = active | watch | blocked`。
- `MarketEnvironment.market_state = attack | normal | cautious | defensive | unknown`。

**不做**

- 不一次性把现有全链路 `Dict` 全部替换成 schema。
- 不引入数据库模型。

### P0-2：增加基础测试目录

**目标**

建立最小测试面，保证后续评分和计划规则可回归。

**建议新增**

```text
tests/
├── test_market_environment.py
├── test_sector_scoring.py
├── test_opportunity_scoring.py
├── test_trade_plan.py
└── test_daily_report.py
```

**验收**

- 可以运行 `python -m pytest tests`。
- 不依赖真实 Tushare、AkShare、LLM。
- 只测试纯函数和 fixture。

## 5. P1 任务

### P1-1：市场环境 MVP

**目标**

新增 `market` Module，生成 `M_market_environment.json/.md`。

**建议新增文件**

```text
tradingagents/market/__init__.py
tradingagents/market/environment.py
tradingagents/market/render.py
```

**数据策略**

V1 先用可获得数据构造 MVP：

- 使用 `get_daily_universe` 或同源日线数据统计强势股数量。
- 成交额优先使用 universe 中 `amount` 的聚合。
- 指数趋势、涨跌停情绪缺失时输出 `unknown` 子项，不阻断主流程。
- `market_state=unknown` 时不强行阻止交易计划，但要在日报标注数据缺口。

**验收**

- `screen-analyze` 运行后出现 `M_market_environment.json/.md`。
- 市场分可解释，包含 `reasons` 和 `data_gaps`。
- 防守市场可被测试构造出来。

### P1-2：板块评分增强

**目标**

在现有 `calibrate_with_sector` 基础上扩展 **板块语境** 评分，不破坏旧字段。

**涉及文件**

```text
tradingagents/sector/sector_calibrator.py
tradingagents/sector/__init__.py
```

**新增字段**

| 字段 | 说明 |
|---|---|
| `sector_adapter` | V1 固定为 `industry` |
| `sector_score` | 0-100 |
| `sector_state` | mainline/strong/watch/weak |
| `sector_rank` | 板块排名 |
| `sector_count` | 板块内候选数 |

**验收**

- `B_sector_calibration.json` 兼容旧字段。
- 新字段可被 `OpportunityScore` 直接使用。
- `unknown_sector` 有保守评分。

### P1-3：机会评分

**目标**

新增 `opportunity` Module，生成 `O_opportunity_scores.json/.md`。

**建议新增文件**

```text
tradingagents/opportunity/__init__.py
tradingagents/opportunity/scorer.py
tradingagents/opportunity/render.py
```

**评分输入**

- `MarketEnvironment`
- 粗筛/结构字段
- `SectorScore`
- `DecisionCard`
- story payload

**V1 默认评分画像**

```text
市场环境 10%
板块强度 20%
个股强度 20%
量价结构 15%
策略匹配 10%
AI/故事真实性 10%
买点质量 10%
风险惩罚 15%
```

**验收**

- 输出 S/A/B/C。
- 输出 `scoring_profile`。
- `enable_ai=False` 时仍可评分。
- 不混淆 **候选股** 和 **重点机会**。

### P1-4：交易计划

**目标**

新增 `planning` Module，生成 `P_trade_plans.json/.md`。

**建议新增文件**

```text
tradingagents/planning/__init__.py
tradingagents/planning/trade_plan.py
tradingagents/planning/render.py
```

**规则**

- 只为 S/A 或满足 `min_plan_grade` 的 **重点机会** 生成计划。
- **防守市场** 下 `max_position_pct=0`，`plan_status=watch|blocked`。
- AI 高分不能提高仓位。
- 风险高、证据弱、信息缺口大可以降级或 blocked。

**验收**

- 计划文案是条件式，不出现“买入 XX”命令。
- S/A 正常市场有 entry/stop/invalidation/position。
- 防守市场下没有新增仓位计划。

### P1-5：每日报告

**目标**

新增 `reporting` Module，生成 `R_daily_report.json/.md`，成为 V1 主入口。

**建议新增文件**

```text
tradingagents/reporting/__init__.py
tradingagents/reporting/daily_report.py
tradingagents/reporting/render_markdown.py
```

**报告结构**

1. 今日市场状态。
2. 板块语境排名。
3. 候选股总览。
4. S/A 重点机会。
5. 交易计划。
6. 明日观察清单。
7. 风险和数据缺口。
8. 复盘钩子。

**验收**

- `R_daily_report.json` 是 source of truth。
- `R_daily_report.md` 从 JSON 渲染。
- 人工打开 Markdown 能回答：今天能不能做、主线在哪、重点看什么、什么条件才行动、错了怎么办。

## 6. P2 任务

### P2-1：Dashboard 读取每日报告

**目标**

让 `dashboard` 优先读取 `R_daily_report.json`，缺失时回退 A/B/C/D/E。

**涉及文件**

```text
cli/main.py
```

**验收**

- 新日期有日报时展示市场状态、重点机会、计划数量。
- 老日期没有日报时仍能展示原摘要。

### P2-2：前向验证增强

**目标**

把三日追踪扩展为 **计划前向验证**。

**涉及文件**

```text
tradingagents/iteration/tracker.py
tradingagents/iteration/review_engine.py
tradingagents/pipelines/iteration_pipeline.py
```

**新增能力**

- 未来 1/5/10/20 日收益。
- 最大涨幅和最大回撤。
- 按 grade、strategy、risk、sector_state、scoring_profile 分组。
- `entry_triggered=true/false/unknown`。

**验收**

- 不推断真实用户执行。
- 补丁建议引用分组证据。

### P2-3：流水线瘦身

**目标**

在 P1 产物稳定后，减少 `stock_analysis_pipeline.py` 的职责。

**建议拆分**

| 新 Module | 职责 |
|---|---|
| `reporting/artifact_writer.py` | JSON/Markdown 文件写入 |
| `reporting/render_*` | Markdown 渲染 |
| `pipelines/trace_builder.py` | trace log |
| `pipelines/stock_analysis_steps.py` | 阶段编排 |

**验收**

- `run_stock_analysis_pipeline` 外部 Interface 不变。
- 旧 CLI 不需要改调用方式。

## 7. 不进入近期开发的事项

| 事项 | 原因 |
|---|---|
| HTML 日报 | 已确认不进 V1 |
| 数据库 | V1 使用文件产物 |
| 实时盘中提醒 | V1 是盘后系统 |
| 观察名单管理 | V1 只生成明日观察清单 |
| 自动应用补丁 | 需要人工审核 |
| 单票深度研究统一评分 | V1 机会评分只服务批量 A 股筛选 |
| 多板块 Adapter 插件化 | V1 只实现 `industry` adapter |

## 8. 推荐开发顺序

按最小风险和最大复用排序：

1. `P0-1` schema 契约。
2. `P0-2` tests 目录和 fixture。
3. `P1-1` 市场环境 MVP。
4. `P1-2` 板块评分增强。
5. `P1-3` 机会评分。
6. `P1-4` 交易计划。
7. `P1-5` 每日报告。
8. `P2-1` Dashboard 读取日报。
9. `P2-2` 前向验证增强。
10. `P2-3` 流水线瘦身。

## 9. 第一轮开发建议

第一轮只做一条可运行纵向切片：

```text
schema
-> market environment fallback/MVP
-> sector score fields
-> opportunity score
-> trade plan
-> daily report json/md
```

先不做：

- CLI 新参数。
- HTML。
- 数据库。
- 多周期复盘。
- 流水线大重构。

第一轮完成后，`screen-analyze` 应额外生成：

```text
M_market_environment.json/.md
O_opportunity_scores.json/.md
P_trade_plans.json/.md
R_daily_report.json/.md
```

旧产物仍然保留：

```text
A_candidates.json/.md
B_sector_calibration.json/.md
B_story_analysis.json/.md
C_ai_analysis_with_cards.json/.md
S_theme_heatmap.json/.md
Z_pipeline_trace_log.json/.md
```
