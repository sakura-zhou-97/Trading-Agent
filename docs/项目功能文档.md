# Trading-Agent 产品功能文档

> 本文从产品视角描述 Trading-Agent 的功能、用户价值、使用场景、功能边界与后续演进方向。本文不展开代码实现细节，重点回答：这个产品服务谁、解决什么问题、提供哪些能力、用户如何使用、输出什么结果、当前有什么限制。

## 1. 产品概述

Trading-Agent 是一套面向股票研究与交易辅助决策的智能投研产品。它通过多智能体协作、行情与新闻数据整合、A 股候选筛选、故事性分析、决策卡生成和复盘迭代，帮助用户把“发现机会、理解机会、评估风险、跟踪结果、优化规则”串成一个可重复的工作流。

产品不直接执行交易，也不替代人工投资判断。它的核心定位是：

**为投研和交易人员提供结构化、可解释、可追踪的股票分析辅助系统。**

## 2. 产品目标

### 2.1 核心目标

1. **提升发现效率**：从大量股票中快速筛出值得关注的候选。
2. **提升分析质量**：把行情、板块、新闻、基本面、题材故事和风险因素整合为统一分析视角。
3. **提升决策可读性**：将复杂分析压缩成标准化决策卡，便于人工快速复核。
4. **提升复盘能力**：跟踪入选股票后续表现，反向发现规则和 Prompt 的问题。
5. **形成迭代闭环**：将复盘结果沉淀为规则补丁和 Prompt 补丁，实现持续优化。

### 2.2 非目标

当前产品不定位为：

- 自动下单系统。
- 投资顾问或收益承诺工具。
- 高频交易系统。
- 完整量化回测平台。
- 面向普通散户的一键买卖推荐 App。

## 3. 目标用户

### 3.1 A 股短线研究人员

**核心诉求**：

- 每天快速知道哪些股票异动明显。
- 判断异动背后是板块推动、题材推动、资金推动，还是纯情绪波动。
- 希望用统一格式记录个股逻辑和风险。

**产品价值**：

- 自动生成候选池、板块校准、故事分析和决策卡。
- 减少人工浏览行情、新闻和概念资料的时间。
- 输出适合盘前/盘后复核的 Markdown 和 JSON 结果。

### 3.2 投研团队负责人

**核心诉求**：

- 让团队的研究输出更标准化。
- 能够追踪“当初为什么选这只股票”。
- 能够复盘规则是否有效，而不是只凭印象调整。

**产品价值**：

- 决策卡字段统一，便于团队协同。
- Trace Log 保留每一步输入与输出，便于审查。
- 迭代系统提供样本表现、最大回撤和补丁建议。

### 3.3 量化/策略研究人员

**核心诉求**：

- 将主观投研经验结构化。
- 把规则、Prompt、数据表现放到同一套流程里验证。
- 快速试验不同模型和不同分析方式。

**产品价值**：

- 支持多模型供应商。
- 支持规则兜底与 AI 分析并存。
- 能够通过补丁池管理规则和 Prompt 调整。

### 3.4 AI 金融应用开发者

**核心诉求**：

- 快速搭建金融多智能体分析原型。
- 验证不同 Agent 分工、数据工具和 Prompt 流程。
- 将单票分析和批量筛选结合起来。

**产品价值**：

- 内置分析师、研究员、交易员、风控等角色。
- 提供完整 CLI 工作台和结果输出目录。
- 适合继续扩展为 Web 面板、自动报告系统或研究工作流平台。

## 4. 用户痛点

### 4.1 信息分散

股票分析通常需要同时查看行情、均线、成交量、板块强度、新闻、公告、基本面、概念题材和市场情绪。信息源分散，人工切换成本高。

### 4.2 候选太多，注意力有限

每天涨幅较大的股票很多。用户需要快速区分“真正值得跟踪的候选”和“只是短期噪音的异动”。

### 4.3 分析口径不统一

不同人写出的股票分析格式不同，导致团队复核和复盘困难。很多关键字段容易缺失，例如最大风险、反转条件、信息缺口。

### 4.4 题材故事难以沉淀

A 股短线研究中，题材和叙事很重要。但题材逻辑往往口语化、碎片化，难以形成可复查的证据链。

### 4.5 复盘不系统

很多系统只负责“当天选股”，不负责跟踪后续表现。没有 T+1/T+2/T+3 和回撤数据，就很难知道规则到底好不好。

### 4.6 规则优化缺少闭环

即使发现误判，也常常只是在脑中调整经验，没有沉淀为明确的规则变更或 Prompt 变更。

## 5. 产品核心价值

### 5.1 从“分析一次”到“持续迭代”

产品不是只生成一次股票分析，而是覆盖：

```text
发现候选 -> 生成分析 -> 人工复核 -> 后续追踪 -> 复盘原因 -> 生成补丁 -> 应用优化
```

这使它更接近投研团队的真实工作方式。

### 5.2 从“模型回答”到“结构化决策卡”

产品不会只输出一段大模型长文，而是将分析压缩为标准字段：

- 结论类型
- 阶段判断
- 证据链
- 可交易性
- 可持续性
- 预期差
- 结构位置
- 最大风险
- 反转触发条件
- 信息缺口

这让结果更容易横向比较，也更适合人工审阅。

### 5.3 从“看个股”到“看板块语境”

A 股个股短线表现经常受板块和题材影响。产品在个股决策前引入板块校准，帮助用户回答：

- 这只股票是不是处在强板块中？
- 它是不是板块内领涨？
- 板块趋势是否支持个股继续表现？
- 个股上涨是孤立异动，还是板块共振？

### 5.4 从“题材热闹”到“证据硬度”

两层故事分析会区分：

- 有证据支持的硬事实。
- 仅由概念、板块或资金热度推断出来的市场叙事。
- 当前缺少的关键信息。

这有助于防止把市场传闻、概念标签和公司实质进展混为一谈。

## 6. 产品功能总览

| 功能模块 | 用户问题 | 产品能力 | 核心输出 |

| 单票多智能体分析 | 这只股票能不能买、持有或卖出？ | 多角色协作分析行情、新闻、情绪、基本面和风险 | 完整分析报告、BUY/HOLD/SELL |
| A 股候选筛选 | 今天哪些强势股值得看？ | 按涨幅、主板、非 ST、结构特征生成候选池 | A 候选清单 |

| 故事性分析 | 这只股票市场在讲什么故事？ | 分析新闻、概念、证据硬度、催化和风险缺口 | 故事卡、故事摘要 |
| AI 决策卡 | 如何快速复核个股？ | 标准化输出交易研究字段 | 决策卡、5 行卡片 |
| 主题热度 | 今天热点集中在哪里？ | 汇总行业数量、平均涨幅和故事标签 | 主题热度统计 |
| 三日追踪 | 之前选出的股票后来怎么样？ | 跟踪 T+1/T+2/T+3 收益和最大回撤 | 追踪指标 |

| Dashboard | 如何快速看当天结果？ | 控制台汇总关键指标和候选摘要 | 控制台面板 |

## 7. 典型用户旅程

### 7.1 日常盘后筛选流程

**用户目标**：盘后快速整理今日强势股票，筛出明天值得关注的候选。

流程：

1. 用户输入交易日期，启动股票筛选。
2. 系统拉取当日 A 股涨幅候选。
3. 系统过滤非主板、ST、涨幅不足股票。
4. 系统补充近 30 日结构特征。
5. 系统生成粗筛候选池。
6. 系统进行板块校准。
7. 系统分析每只股票的故事热度或故事卡。
8. 系统生成每只股票的决策卡。
9. 用户查看候选清单、主题热度和个股卡片。
10. 用户人工决定是否加入观察或交易计划。

用户获得：

- 当日候选池。
- 板块强弱判断。
- 每只股票的 5 行决策卡。
- 风险和反转条件。

### 7.2 深度题材研究流程

**用户目标**：对某批候选做更深入的题材和故事性分析。

流程：

1. 用户选择 two_layer 故事模式。
2. 系统为每只股票抓取新闻、基本面和概念标签。
3. 系统生成“市场正在讲什么故事”。
4. 系统判断哪些内容是硬证据，哪些只是推断。
5. 系统生成近 1-3 个月潜在催化。
6. 系统合成完整故事卡。
7. 用户查看主故事、亮点、缺点、资金为何来和降级规则。

用户获得：

- 市场印象。
- 一句话总结。
- 主故事 A/B。
- 证据硬度。
- 信息缺口。
- 降级条件。

### 7.3 单票完整研究流程

**用户目标**：围绕一只股票做类似投研小组的完整分析。

流程：

1. 用户输入股票代码和日期。
2. 用户选择分析师角色、模型供应商和研究深度。
3. 系统运行行情、新闻、情绪和基本面分析。
4. 多空研究员展开辩论。
5. 研究经理形成投资计划。
6. 交易员形成交易方案。
7. 风控角色从激进、中性、保守角度辩论。
8. 系统输出最终交易决策。
9. 用户选择保存完整报告。

用户获得：

- 分析师分段报告。
- 多空辩论过程。
- 交易计划。
- 风控意见。
- 最终 BUY/HOLD/SELL。

### 7.4 复盘迭代流程

**用户目标**：检查过去入选股票后续表现，优化筛选规则和分析 Prompt。

流程：

1. 用户选择交易日期和回看天数。
2. 系统加载过去若干日的入选股票。
3. 系统计算每只股票 T+1/T+2/T+3 收益。
4. 系统计算三日最大回撤。
5. 系统标记是否建议剔除。
6. 系统总结样本表现。
7. 系统生成规则补丁和 Prompt 补丁。
8. 用户查看补丁池，选择采纳或拒绝。
9. 用户应用已采纳补丁。

用户获得：

- 入选股票后续表现。
- 亏损和回撤样本。
- 规则优化建议。
- Prompt 优化建议。
- 可追踪的补丁记录。

## 8. 功能模块详述

## 8.1 单票多智能体分析

### 功能说明

该功能面向“我想深入研究某只股票”的场景。系统模拟一个投研团队，将不同分析角色串联起来，最终输出交易辅助判断。

### 用户输入

- 股票代码。
- 分析日期。
- 分析师组合。
- 研究深度。
- 模型供应商和模型。
- 可选的模型推理强度配置。

### 系统处理

产品层面可理解为 5 个阶段：

1. **信息采集**：行情、技术指标、新闻、基本面。
2. **分析师报告**：不同角色分别输出专业视角。
3. **多空辩论**：看多与看空角色相互质询。
4. **交易计划**：交易员形成可执行建议。
5. **风险裁决**：风控团队评估风险，输出最终意见。

### 用户输出

- 完整分析报告。
- 分段分析内容。
- 交易计划。
- 风险意见。
- BUY/HOLD/SELL 信号。

### 产品价值

- 适合对重点标的做完整研究。
- 输出过程可读，不只是一个结论。
- 可通过不同模型和研究深度控制成本与质量。

### 当前限制

- 结果依赖 LLM 输出质量和数据源质量。
- 多角色分析会消耗较多模型调用。
- 最终信号仍需人工判断，不应直接自动交易。

## 8.2 A 股候选筛选

### 功能说明

该功能面向“每天从 A 股市场找出值得关注的强势候选”的场景。

系统先从交易日行情中找到涨幅满足条件的股票，再通过主板、非 ST、结构特征等条件形成候选池。

### 用户输入

- 交易日期。
- 最低涨幅阈值。
- 最大候选数量。
- 是否启用 AI 精筛。
- 故事分析模式。

### 系统处理

产品层面分为：

1. **市场扫描**：读取当日股票表现。
2. **硬条件过滤**：排除不符合基础条件的股票。
3. **结构补充**：补充均线、量能、趋势和突破等信息。
4. **标签生成**：给每只候选打上结构标签。

### 用户输出

- 候选股票代码、名称、行业、涨幅。
- 结构标签。
- 基础行情字段。
- Markdown 候选清单。

### 产品价值

- 将每日初筛从人工浏览变为自动生成。
- 保留全量通过硬规则的候选，不因排序过早丢失样本。
- 为后续板块、故事和决策卡提供统一输入。

### 当前限制

- 目前更偏“硬过滤”，不是完整评分选股系统。
- 候选池质量高度依赖交易日数据完整度。
- 当前 `top_n` 更像兼容参数，不代表最终只分析前 N 只。

## 8.3 板块校准

### 功能说明

板块校准用于回答：这只股票的异动有没有板块语境支持？

系统会按行业聚合候选，判断行业整体强度、三日趋势和龙头状态，然后把板块上下文写回每只股票。

### 用户输入

用户不需要单独输入。该功能在 A 股筛选流程中自动执行。

### 系统输出

- 行业当日强度。
- 行业三日趋势。
- 板块龙头。
- 龙头状态。
- 个股板块乘数。
- 校准原因。

### 产品价值

- 帮助用户区分“板块共振”和“个股孤立异动”。
- 决策卡会引用板块证据，让结论更完整。
- 适合 A 股短线交易中对主线和分支的判断。

### 当前限制

- 当前板块口径主要依赖股票行业字段，不等同于更细颗粒度的题材板块。
- 板块强弱是基于候选池内部统计，不是全市场行业指数。

## 8.4 故事性分析

### 功能说明

故事性分析用于回答：市场为什么关注这只股票？它的题材逻辑是否有证据支撑？

产品提供两种模式：

| 模式 | 适用场景 | 特点 |
|---|---|---|
| simple | 日常快速跑批 | 统计新闻数量和关键词热度 |
| two_layer | 深度题材研究 | 生成叙事、时间轴、故事卡和证据缺口 |

### simple 模式

用户获得：

- 新闻条数。
- 关键词命中。
- 热度等级。
- 是否主线候选。
- 是否有风险提示。

适合快速批量筛选。

### two_layer 模式

用户获得：

- 市场印象。
- 一句话总结。
- 公司基础描述。
- 市场复读叙事。
- 公司方向。
- 亮点与缺点。
- 证据硬度。
- 近端催化。
- 资金为何愿意来。
- 降级规则。
- 主故事 A/B。
- 信息缺口。

适合重点标的深度分析。

### 产品价值

- 把“市场故事”从口头描述变为结构化卡片。
- 明确区分硬证据和推断。
- 帮助用户识别概念标签和公司实质进展之间的差距。

### 当前限制

- two_layer 模式调用成本更高，不适合无限制全市场运行。
- 如果新闻和基本面数据不足，故事卡会体现信息缺口，但深度会受影响。
- LLM 输出可能不稳定，需要结合 Prompt IO 和人工复核。

## 8.5 AI 决策卡

### 功能说明

AI 决策卡是 A 股筛选流程的核心可读输出。它把每只候选股票转化为统一格式，方便用户横向比较。

### 决策卡字段

| 字段 | 用户关心的问题 |
|---|---|
| 结论类型 | 这是趋势、情绪还是混合驱动？ |
| 阶段 | 当前处于启动、加速、调整还是二次启动？ |
| 证据链 | 判断依据是什么？ |
| 可交易性 | 是否适合短线参与？ |
| 可持续性 | 逻辑能不能延续？ |
| 预期差 | 市场是否已经充分定价？ |
| 结构位置 | 当前价格位置是否安全？ |
| 最大风险 | 最主要的亏损来源是什么？ |
| 反转触发条件 | 出现什么信号要改变看法？ |
| 信息缺口 | 还缺哪些关键数据？ |

### 产品价值

- 极大降低人工快速浏览成本。
- 强制每只股票都输出风险和反转条件。
- 便于投研团队用统一语言讨论候选。

### 兜底机制

如果 AI 不可用或输出异常，系统会生成规则兜底卡。用户可以在分析记录中看到该卡是 AI 生成还是 fallback 生成。

### 当前限制

- AI 决策卡是辅助判断，不代表交易指令。
- 卡片质量依赖输入数据和 Prompt 质量。
- 对缺失数据场景，需要人工特别关注 `info_gaps`。

## 8.6 主题热度

### 功能说明

主题热度用于帮助用户快速看出当天候选集中在哪些方向。

### 用户输出

- 候选最多的行业。
- 行业平均涨幅。
- 风险类标签数量。
- 主线/龙头/题材类标签数量。
- 突破/涨停/加速类标签数量。

### 产品价值

- 适合盘后快速判断今日市场风格。
- 帮助用户把个股卡片放到整体热点中理解。

### 当前限制

- 当前统计更偏行业聚合，不是完整的题材热力图。
- 主题标签来自文本关键词统计，存在语义粗糙问题。

## 8.7 三日追踪复盘

### 功能说明

三日追踪用于回答：前几天选出的股票，后面到底涨了还是跌了？

系统会自动加载历史入选候选，计算后续三天表现。

### 用户输出

- T+1 收益。
- T+2 收益。
- T+3 收益。
- 三日最大回撤。
- 每日涨跌原因。
- 涨跌标签。
- 是否建议剔除。
- 入选时决策卡快照。

### 产品价值

- 让筛选系统具备反馈机制。
- 帮助用户发现“看起来强但次日兑现”的样本。
- 形成规则和 Prompt 优化的数据依据。

### 当前限制

- 三日窗口适合短线复盘，不适合中长期策略评价。
- 样本不足时，系统会提示暂缓激进调参。

## 8.8 复盘建议与补丁池

### 功能说明

复盘建议用于把追踪数据转化为可执行的优化建议。补丁池用于管理这些建议的生命周期。

### 补丁类型

| 类型 | 含义 | 示例 |
|---|---|---|
| 规则补丁 | 调整筛选规则或权重 | 强化回撤过滤、降低高位加速权重 |
| Prompt 补丁 | 调整 AI 分析约束 | 增加止损位要求、强化兑现识别 |

### 状态流转

```text
proposed -> accepted -> applied
proposed -> rejected
```

### 产品价值

- 将复盘经验沉淀为明确修改建议。
- 允许人工审核后再应用，避免自动调参失控。
- 保留补丁来源、证据、置信度和状态。

### 当前限制

- 补丁应用是规则化写入，不会自动证明收益改善。
- 应用后仍需要通过后续交易日继续验证。

## 8.9 Dashboard 与交互式工作台

### Dashboard

Dashboard 提供指定日期结果概览：

- A 候选数量。
- B 板块校准数量。
- C 决策卡数量。
- D 追踪数量。
- E 补丁数量。
- Top 候选摘要。
- 追踪样本摘要。

### 交互式工作台

交互式工作台将常用操作放入菜单：

- 运行股票筛选。
- 运行复盘迭代。
- 一键日常流程。
- 查看 Dashboard。
- 查看个股决策卡。
- 管理补丁状态。
- 应用已采纳补丁。
- 运行单票完整分析。

### 产品价值

- 降低命令记忆成本。
- 适合非开发用户在终端中使用。
- 将“分析、查看、复盘、应用补丁”放到同一工作台。

## 11. 产品边界与风险提示

### 11.1 金融风险

产品输出仅用于研究辅助，不构成投资建议。用户需要自行承担投资决策风险。

### 11.2 数据风险

数据源可能存在：

- 延迟。
- 缺失。
- 字段变更。
- 接口限流。
- 新闻覆盖不完整。

这些问题会影响候选筛选、故事分析和决策卡质量。

### 11.3 模型风险

LLM 可能出现：

- 事实理解错误。
- JSON 输出异常。
- 过度推断。
- 对缺失信息处理不充分。
- 对题材热度过度乐观或过度保守。

产品通过证据硬度、信息缺口、fallback 和 Trace Log 降低风险，但不能完全消除。

### 11.4 策略风险

短线股票波动大，强势候选也可能快速回撤。三日追踪和补丁建议只能帮助发现问题，不能保证后续收益。

## 12. 当前产品成熟度评估

| 维度 | 当前状态 | 说明 |
|---|---|---|
| 单票分析 | 可用 | 已形成完整多智能体链路 |
| A 股日常筛选 | 可用 | 支持候选、板块、故事、决策卡 |
| 深度故事分析 | 可用但成本较高 | 适合重点标的，不适合无限制全量跑 |
| 决策卡标准化 | 较成熟 | 字段明确，支持 AI 和 fallback |
| 复盘追踪 | MVP 可用 | 支持三日表现与回撤 |
| 补丁闭环 | MVP 可用 | 支持建议、状态和应用 |
| Dashboard | 基础可用 | 目前是控制台摘要 |
| 非技术用户体验 | 初级 | 仍以 CLI 为主，缺少 Web UI |

## 13. 推荐使用方式

### 13.1 日常快速筛选

适合盘后常规使用：

1. 运行日常流程。
2. 查看 Dashboard。
3. 打开当日决策卡。
4. 人工选出观察名单。

建议使用 simple 故事模式，速度和成本更可控。

### 13.2 重点题材深挖

适合对少量候选做深度研究：

1. 限制候选数量。
2. 启用 two_layer 故事模式。
3. 查看故事卡和 Prompt IO。
4. 重点关注证据硬度和 data gaps。

### 13.3 每周策略复盘

适合策略维护：

1. 汇总一周内每日筛选结果。
2. 运行三日追踪。
3. 查看回撤和胜率。
4. 审核补丁池。
5. 只采纳有样本支撑的补丁。

## 14. 产品指标建议

后续如果要产品化，建议跟踪以下指标：

### 14.1 使用指标

- 每日运行次数。
- 每次候选数量。
- 决策卡查看数量。
- two_layer 模式使用比例。
- 补丁采纳率。

### 14.2 质量指标

- T+1/T+2/T+3 平均收益。
- T+3 胜率。
- 三日平均最大回撤。
- fallback 占比。
- LLM JSON 解析失败率。
- 新闻/基本面缺失率。

### 14.3 业务指标

- 人工复核耗时下降比例。
- 入选候选被人工采纳比例。
- 补丁应用后指标改善情况。
- 不同模型下的决策卡质量评分。

## 15. 后续产品演进建议

### 15.1 P0：增强当前 MVP 的可用性

- 增加数据源健康检查。
- 增加运行前配置检查。
- 将 fallback、AI 失败、数据缺失在结果中更醒目标注。
- 增强 Dashboard 的可读性。
- 增加基础测试样例，避免规则补丁破坏主流程。

### 15.2 P1：提升投研使用体验

- 增加 Web 界面。
- 支持按股票、行业、日期检索历史决策卡。
- 支持观察名单管理。
- 支持候选人工打标：关注、剔除、已验证、误判。
- 支持导出日报或周报。

- 将三日追踪扩展到多周期追踪。
- 增加分组表现统计：按行业、标签、阶段、结论类型。
- 支持补丁应用前后的效果对比。

### 15.4 P3：增强智能分析能力

- 增加公告和研报数据。
- 增加资金流、龙虎榜、北向资金等更细数据。
- 增加题材图谱和概念扩散分析。
- 为故事卡引入更严格的结构化校验。
- 支持多模型结果对比和投票。

## 16. 一句话总结

Trading-Agent 当前最核心的产品价值是：

**把股票研究中的候选发现、题材理解、风险判断、结构化决策和后续复盘连接成一个可持续迭代的智能投研工作流。**
